# Training Layer

Loads labeled feature vectors, splits them into train/val/test sets, and fits a model. Parallel to the inference layer — neither imports from the other.

**Consumes:** `FeatureVector` parquet files (written by `FeaturePipeline`) + researcher-supplied `labels.csv`

**Emits:** Saved model directory (via `model.save()`)

```
src/ml4em/training/
  base.py       Trainer Protocol
  dataset.py    FeatureDataset — load features + join labels
  trainer.py    StandardTrainer
```

## `Trainer` Protocol { #trainer }

The contract every trainer must satisfy.

```python
@runtime_checkable
class Trainer(Protocol):
    def fit(self, dataset: FeatureDataset) -> None: ...
    def save(self, path: str) -> None: ...
```

`fit` takes **one** `FeatureDataset` — not a `(train, val)` pair. The trainer performs the
split itself using `val_fraction`, `test_fraction` and `seed` from `TrainingConfig`, so
the split is reproducible from configuration rather than from however the caller happened
to divide the data. The model architecture and its own config are passed to the concrete
trainer at construction time, not through this Protocol.

## `FeatureDataset` { #featuredataset }

Joins `FeatureVector` objects with a researcher-supplied label per `source_id` and
produces `LabeledSample`s.

**Emits:** `list[LabeledSample]` — `FeatureVector` + integer label, joined on `source_id`

There are two construction paths.

=== "From disk (`from_storage`)"

    Reads every `*.parquet` file in `storage.features_dir` and a labels CSV. Use this for
    production runs where feature extraction and training are separate jobs.

    ```python
    from ml4em.training import FeatureDataset

    dataset = FeatureDataset.from_storage(cfg.storage, labels_path="labels.csv")
    ```

=== "From memory (`from_feature_vectors`)"

    Takes `FeaturePipeline.run_batch()` output and a `dict[source_id, label]` directly.
    No disk I/O. Use this for the demo and for single-process runs.

    ```python
    dataset = FeatureDataset.from_feature_vectors(feature_vectors, labels={"123": 1})
    ```

Both paths silently drop sources present in only one of (features, labels). A join is
expected to be partial — a label file covering the whole sky would not be a label file.

```python
print(dataset.class_counts())       # {0: 5000, 1: 320}
print(dataset.positive_fraction())  # 0.060  — counts label == 1 only

train, val, test = dataset.split(val_fraction=0.1, test_fraction=0.1, seed=42)
```

`split()` shuffles with a seeded `random.Random` and slices; it is **not stratified**, so
class balance is not preserved across splits. Both fractions must be in (0, 1) and must
sum to less than 1.

`class_counts()` is the general accessor. `positive_fraction()` counts `label == 1`
specifically and is therefore only meaningful for a binary problem.

### Labels CSV format

```csv
source_id,label
686149073900013696,1
686149073900013697,0
```

- `source_id`: same string ID as `LightCurve.source_id`
- `label`: a **non-negative class index**. `0`/`1` is the binary case, but any
  non-negative integer is accepted — the feature store is not specific to binary
  classification and a multi-class head is an equally valid consumer of it. Negative
  values are rejected, since they are almost always a parse error rather than a real class.

Labels are never generated by ml4em. See [Preparing Labels](../guides/label-preparation.md) for sourcing them from external catalogs.

## Parquet round trip { #parquet }

`FeatureDataset.save_feature_vectors(feature_vectors, "features/batch_001.parquet")`
persists a batch so a later job can reload it without re-running GPU feature extraction.
`_load_features()` reverses everything below, so a model sees the same input whether
features came from memory or from disk.

Most fields map to columns directly. Three do not:

**`dmdt`.** Parquet has no 2-D cell type but does have `list<double>`, so the histogram is
stored flat in `dmdt_flat` with its shape in `dmdt_rows` and `dmdt_cols`, and rebuilt on
load. A `None` histogram writes all three columns as null and reloads as `None`.

**`period_top` and `significance_top`.** These are dicts of variable-length lists, which
parquet has no useful representation for, and downstream models want flat columns anyway.
Each becomes one column per (rank, algorithm) pair: `period_0_CE`, `period_1_CE`, …,
`significance_0_CE`, …. On load the pattern is matched anchored at the start of the name
and requiring digits in the rank position, so scalar fields that share the prefix —
`period_significance`, `period_agree_score` — are left alone.

**The optional Gaia floats.** `None` is stored as NaN and restored to `None` on load, so
"no counterpart" survives the round trip as itself rather than becoming a number.

Loading tolerates schema drift in both directions and warns once, not per row:

- Columns the current `FeatureVector` no longer declares are dropped, with a warning. The
  warning matters because silently discarding columns is exactly how a schema change turns
  into a model quietly trained on fewer features than the file contains.
- Fields absent from the parquet are left at their dataclass defaults, also with a warning.

## `StandardTrainer` *(shell)* { #standardtrainer }

Model-agnostic driver. It accepts any object satisfying `MLModel` and takes loop
hyperparameters from `TrainingConfig`. Architecture-specific decisions — hidden dims,
dropout, tree count — live in the model's own config, not here.

**Consumes:** `FeatureDataset` + `MLModel`

**Emits:** Saved model directory

```python
from ml4em.training import StandardTrainer

trainer = StandardTrainer(model, cfg.training)
trainer.fit(dataset)   # NotImplementedError — training loop pending
trainer.save(path)     # delegates to model.save(path) — implemented
```

### `cfg.training` parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `learning_rate` | `3e-4` | Step size for gradient descent (neural net trainers) |
| `batch_size` | `64` | Samples per gradient update |
| `max_epochs` | `100` | Maximum training epochs |
| `patience` | `20` | Early stopping: halt after this many epochs with no val improvement |
| `val_fraction` | `0.1` | Fraction of data held out for validation |
| `test_fraction` | `0.1` | Fraction of data held out for final evaluation |
| `seed` | `42` | Random seed for reproducibility |

> **Status:** `fit` raises `NotImplementedError` with implementation notes in the message.
> The loop depends on the model backend — a PyTorch model needs an explicit epoch loop
> with early stopping, a gradient-boosting model does its own — so it is left until the
> architecture is settled rather than guessed at. `save` is fully implemented and
> delegates to `model.save(path)`.
>
> In the meantime, `LogisticExampleClassifier` carries its own `fit(features, labels)`
> and can be trained directly. See [Models](models.md#logistic-example).
